Code review signal or noise

What if AI finds problems because we asked it to?

AI code review sounds useful. More eyes on the code should mean more bugs caught. But there is a simple problem: if you ask AI to find problems, it may keep finding things even when the code is already fine.

The question is not "can AI review code?" The question is: which comments matter, and which ones just waste time?

The question

Say CodeRabbit reviews your code and finds problems. You fix them. Then Copilot reviews the same work and finds new problems. Are those real problems? Or did the tool find something because its job was to find something?

Some AI comments are useful. Some are not. The test is simple: did the comment help the code, or did it just create more work?

What I found

Warning sign

Many AI comments do not get used.

One study looked at 16 AI code review tools. Valid AI comments led to code changes 0.9% to 19.2% of the time. Human comments led to changes 60% of the time.

Warning sign

AI can make good code worse.

In one test, correct code got bad AI suggestions up to 24.8% of the time. So every AI fix still needs proof.

Warning sign

The prompt can change the answer.

Research on AI judges found that small changes in wording can change how AI scores code, even when the code did not change.

Good sign

AI can help when it is filtered.

Atlassian tested an AI reviewer that checked facts and removed weak comments. Its comments led to fixes 38.7% of the time.

Good sign

AI can also cut down false alarms.

A Tencent study found that AI plus static analysis removed 94% to 98% of false alarms.

Tradeoff

AI can move work, not remove it.

One study found humans wrote 11.8% more review comments when reviewing AI-written code.

A small test

This code can be fine if the app already checks price and quantity before this function runs. 

type LineItem = {
  priceCents: number;
  quantity: number;
};

export function subtotalCents(items: LineItem[]) {
  return items.reduce(
    (sum, item) => sum + item.priceCents * item.quantity,
    0
  );
}
AI may still say
  • What if quantity is below zero?
  • What if priceCents is not a whole number?
  • What if the total gets too large?
  • Should this check taxes?
  • Should this check discounts?
These comments are not dumb. They just need context. If the app already checks those rules, the comments are noise. If the app does not check them, the comments are signal.

Signal or noise?

Signal
  • It shows a failing test.
  • It shows a real way the app can break.
  • It points to a rule the code breaks.
  • It protects users or data.
Noise
  • It says "consider" with no clear reason.
  • It asks for a check that already exists.
  • It is just a style opinion.
  • It only appears after asking AI to find more.
Worth doing
  • Ask AI to prove the issue.
  • Ask how bad the issue is.
  • Let AI say "no real issue found."
  • Ignore comments with no test, rule, or risk.

My take

If you tell AI to find problems, it may find problems. That does not mean every comment is worth fixing.

AI review is useful when it points to risk and gives proof. It is weak when it creates extra work with no clear win.

The best use is simple: AI finds possible issues, tests and tools check them, and humans decide what matters.
